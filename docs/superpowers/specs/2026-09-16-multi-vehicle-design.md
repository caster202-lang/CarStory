# 다중 차량 전환 설계 (2026-09-16)

## 배경

카스토리는 지금 차량 1대만 다룬다. 정식 오픈 전이라 **사용자가 없고, 지켜야 할 데이터도 없다.**
오픈한 뒤에 이 구조를 바꾸려면 모든 사용자의 localStorage를 옮기는 코드가 필요하고,
그게 틀리면 남의 기록이 사라진다. 지금이 그 코드를 한 줄도 안 쓰고 바꿀 수 있는 마지막 시점이다.

같은 이유로 지금만 공짜인 두 가지를 함께 처리한다: localStorage 키 이름 정리, 브랜드 표시 방식 변경.

## 목표

1. 차량 여러 대를 등록하고 전환할 수 있다
2. 차량마다 소모품·주유·교체 이력이 완전히 분리된다
3. 저장 키 이름을 앱 이름(carstory)에 맞춘다
4. 제조사 로고 대신 브랜드 색 + 브랜드 이름으로 표시한다

## 범위 밖

- PWA 전환, 파일 분리 — 데이터 모양과 무관하므로 오픈 뒤에 해도 비용이 같다
- 차량별 알림 설정, 차량 간 기록 이동 — 필요해진 뒤에 판단한다

## 1. 데이터 구조

저장되는 것과 메모리에 있는 것을 나눈다.

| | 내용 |
|---|---|
| **저장** | `vehicles[]` 차량 목록 · `activeId` 지금 보는 차 · `allItems[]` `allFuel[]` `allLogs[]` 전 차량 기록 (각 항목이 `vehicleId` 보유) |
| **메모리** | `vehicle` `items` `fuelLogs` `maintLogs` — 활성 차량 것만 걸러낸 **뷰** |

핵심은 **기존 전역 이름을 그대로 두는 것**이다. `vehicle`이 계속 "지금 보는 차"를 가리키면,
이 값을 읽기만 하는 코드는 한 줄도 고치지 않아도 된다.
(`index.html`에서 `vehicle`이 등장하는 곳은 88군데이고, 그중 저장하는 곳은 11군데다.)

```
selectVehicle(id)
  activeId  = id
  vehicle   = vehicles에서 id로 찾은 것 (없으면 null)
  items     = allItems 중 vehicleId가 id인 것
  fuelLogs  = allFuel  중 vehicleId가 id인 것
  maintLogs = allLogs  중 vehicleId가 id인 것
```

### 저장은 병합으로

뷰는 복사본이라 `items.push(...)`가 `allItems`에 닿지 않는다.
그래서 저장하는 11곳을 헬퍼로 바꾼다.

```
saveItems()
  allItems = (allItems 중 vehicleId가 activeId가 아닌 것) + (items에 vehicleId를 찍은 것)
  저장
```

`saveFuel()`, `saveLogs()`, `saveVehicles()`도 같은 모양이다.

**왜 읽기가 아니라 쓰기를 고치는가**: 읽는 곳을 전부 filter로 바꾸는 게 정석처럼 보이지만,
하나라도 놓치면 **다른 차 기록이 섞여 보인다**. 눈에 잘 안 띄고 사용자가 먼저 발견한다.
쓰기 11곳은 수가 적고, 틀리면 저장이 즉시 깨져서 바로 드러난다.

## 2. 화면

### 차량 전환

홈 차량 카드를 누르면 등록된 차 목록이 뜬다. 고르면 그 차로 바뀐다.
차량 탭은 지금처럼 **선택된 차의 정보 수정** 역할을 유지한다.

목록 맨 아래 **"차 추가"**를 누르면 목록을 닫고 차량 탭으로 이동해 **빈 폼**을 띄운다.
저장하면 새 차가 만들어지면서 그 차가 활성 차량이 된다.
새 차를 만드는 입구는 이 한 곳뿐이고, 차량 탭을 그냥 열었을 때는 지금처럼
**선택된 차를 수정**하는 화면이다 (새 차가 만들어지지 않는다).

차가 0대면 지금과 똑같은 빈 상태("차량 탭에서 내 차를 등록해주세요")를 보여주고,
카드를 눌러도 목록을 열지 않는다.

### 브랜드 표시

제조사 로고 이미지를 걷어내고 **브랜드 색 칩 + 브랜드 전체 이름**으로 바꾼다.

```
지금     [로고]      제네시스 G80
                     2022년식

바꾼 뒤  [제네시스]  G80
                     2022년식
```

브랜드는 칩이 맡고 제목은 모델명만 남는다. `vehicleTitle()`이 브랜드를 붙이지 않게 고친다.
브랜드가 "기타"면 보여줄 이름이 없으므로 칩 없이 모델명만 표시한다.

이 표시 방식은 새로 만드는 게 아니다. 브랜드 선택 드롭다운이 이미 `색 배지 + 브랜드 이름`으로
그려지고 있어서(`index.html` 968·978행), 홈 카드만 혼자 로고를 쓰고 있었다. 바꾸면 앱 전체가 같아진다.

정리 대상: `LOGO_BASE`, `BRAND_SLUG`, 로고 관련 selfTest 검사 3개, README의 로고 섹션.
브랜드 색(`BRAND_COLOR`)은 그대로 두므로 앱 포인트 색은 바뀌지 않는다.

**이유**: 수익화를 염두에 둔 공개라면 제조사 로고는 브랜드마다 사용 조건을 따로 확인해야 한다.
개인 용도라는 전제가 사라지므로 미리 뺀다.

## 3. 차량 삭제

차량 탭에 "이 차 삭제"를 둔다. 누르면 함께 지워질 기록 건수를 보여주고 확인받는다.

> 제네시스 G80을 지울까요?
> 소모품 12건 · 주유 8건 · 교체 이력 5건이 함께 지워집니다. 되돌릴 수 없어요.

확인하면 그 차의 `vehicleId`를 가진 기록을 `allItems`·`allFuel`·`allLogs`에서 모두 제거한다.
지운 뒤엔 남은 차 중 첫 번째로 전환하고, 남은 차가 없으면 빈 상태로 간다.

주인 없는 기록을 남기지 않는 쪽을 택했다. 안 지우면 쓰지도 않는 데이터가 계속 쌓이고
백업 파일만 커진다.

## 4. 백업

**형식은 3판 그대로 간다.** 2026-09-16에 미리 만들어둔 `vehicles` 배열 자리가 이제 실제로 쓰이는
것이라 판 올림이 필요 없다.

- `vehicles`에 여러 대를 담고 `activeId`를 함께 적는다
- 호환용 `vehicle` 키는 더 이상 **쓰지 않는다**. 다만 **읽기는 계속 지원**해서
  2판 백업과 어제 형식으로 내보낸 파일도 열린다
- 불러오면 `vehicles`가 통째로 교체되고, `activeId`가 목록에 없으면 첫 번째 차로 맞춘다

## 5. localStorage 키 이름

`mile_*` → `carstory_*`로 바꾼다. 데이터 키뿐 아니라 `mile_theme`, `mile_backup`도 함께.

**예전 키를 읽어오는 코드는 넣지 않는다.** 사용자가 없어서 옮길 데이터가 없고,
한 번 넣으면 영구히 들고 다녀야 하는 코드이기 때문이다.

> **작업하면 지금 브라우저에 있는 테스트 기록이 사라진다.**
> 남길 것이 있으면 작업 전에 내보내기를 해두고, 새 버전에서 불러오기로 되살린다.

## 6. 테스트

`index.html?test`의 selfTest에 다음을 추가한다. 모두 실패를 먼저 확인한 뒤 구현한다.

| 검사 | 확인할 것 |
|---|---|
| 기록 격리 | 차 A에서 소모품을 넣어도 차 B의 목록에 안 보인다 |
| 전환 | `selectVehicle`이 네 개 뷰를 모두 그 차 것으로 다시 만든다 |
| 병합 저장 | 차 A에서 저장해도 차 B의 기록이 사라지지 않는다 |
| 연쇄 삭제 | 차를 지우면 그 차의 기록만 사라지고 다른 차 것은 남는다 |
| 백업 왕복 | 두 대를 담아 내보낸 뒤 불러오면 두 대와 각자의 기록이 그대로다 |
| 예전 백업 | 2판·어제 3판 파일을 읽으면 한 대짜리로 정상 복원된다 |
| 브랜드 표시 | 홈 카드에 브랜드 이름이 한 번만 나온다 (제목과 칩에 중복되지 않는다) |

## 알려진 한계

- 차량 간 기록 이동은 없다. 잘못된 차에 넣었으면 지우고 다시 넣어야 한다
- 차량 대수에 제한을 두지 않는다. 화면이 감당 못 할 만큼 등록하는 경우는 고려하지 않는다
- 교체일을 잘못 적었다가 고치면 이력에 옛 날짜 줄이 남는 기존 한계는 그대로다
